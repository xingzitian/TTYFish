# 终端操作与公共界面组件

`Action` 描述操作 ID、主按键、别名、短文字和可选的帮助文字。主按键同时用于显示和匹配；`Range` 表示按键依次对应不同选项，连续数字显示为范围，其余按键逐个显示。用 `ResolveIndexedAction` 获取所选位置，不要从按键字符推算索引。普通动作的别名仍表示同一个操作。游戏保留操作的执行和规则校验；`ResolveAction` 只把当前上下文中的按键转换为 ID。各游戏按当前阶段选择操作列表，模态列表需要在普通列表之前处理。不要把不同场景中作用不同的同名键合并到一份无条件生效的列表中。

极简和丰富界面可以通过 `SelectActions` 从同一份定义生成提示，帮助页使用 `ActionGroup`、`RenderHelp` 和 `HelpViewport`；高度不够时用方向键或 Page Up/Down 查看。`RenderActions` 使用调用方提供的终端样式突出结构化操作中的按键；无色模式也由调用方控制。`WrapTokens` 按终端显示宽度折行，`PlayerRows` 排列玩家徽标，`CyclicWindow` 为座位条提供循环视窗。

普通画面可使用 `FrameViewport`、`MoveFrameOffset` 和 `FrameScrollActions` 在高度不足时滚动，默认用 Ctrl+上/下 或 Ctrl+Page Up/Down；内容过宽时会先按终端宽度折行。这些滚动键属于对应画面的实际生效操作，应纳入该场景的冲突检查。调用方需要保存滚动位置、在窗口尺寸变化时重新计算，并在切换画面时适当地重置。

UNO、爆炸猫和网关将牌桌、大厅、菜单及主要模态操作接入这套定义；`NumberedActions` 可为快捷语等选项生成数字键。`EscapeAction` 提供统一的取消键定义：网关在游戏未占用键盘时处理，打开离开确认后确认框优先。游戏可实现 `DisconnectAction() ui.Action` 方法供网关读取断开键；未实现时网关默认使用 Q。`HelpActions` 从已注册的帮助键派生关闭帮助的操作；老板键和中断键也有公共定义。房间码等自由文本输入仍由输入组件处理；新增迁移时应保持这些上下文的优先顺序，并让展示与处理使用相同的操作定义。

用 `RegisterActions` 注册动作集合时会自动检查重复 ID、主键和别名冲突并返回错误；静态程序配置可用 `MustRegisterActions`，错误会在初始化时明确报出。动态组合的场景可用 `CheckedActions`：它同时检查可见操作和实际生效的通用操作，发现冲突时返回不可触发的错误提示，避免在用户对局期间使宿主进程崩溃。UNO、爆炸猫和网关的静态操作表，以及两款游戏的当前命令集合已接入校验。检查应按实际场景分别进行：例如爆炸猫埋雷时 `I` 属于位置选择，不与普通场景的界面切换同时生效。不同模态可以复用按键；调用方负责先分派当前模态，再处理普通场景。兼容旧代码的裸 `ResolveAction` 不会隐式注册，因此新游戏应使用注册接口，而不要直接分派未经校验的切片。
