# 终端操作与公共界面组件

`Action` 描述操作 ID、主按键、别名、短文字和可选的帮助文字。主按键同时用于显示和匹配；`Range` 从连续数字按键生成范围提示。游戏保留操作的执行和规则校验；`ResolveAction` 只把当前上下文中的按键转换为 ID。各游戏按当前阶段选择操作列表，模态列表需要在普通列表之前处理。不要把不同场景中作用不同的同名键合并到一份无条件生效的列表中。

极简和丰富界面可以通过 `SelectActions` 从同一份定义生成提示，帮助页使用 `ActionGroup` 和 `RenderHelp`。`RenderActions` 使用调用方提供的终端样式突出结构化操作中的按键；无色模式也由调用方控制。`WrapTokens` 按终端显示宽度折行，`PlayerRows` 排列玩家徽标，`CyclicWindow` 为座位条提供循环视窗。

UNO、爆炸猫和网关将牌桌、大厅、菜单及主要模态操作接入这套定义；`NumberedActions` 可为快捷语等选项生成数字键。`EscapeAction` 提供统一的取消键定义：网关在游戏未占用键盘时处理，打开离开确认后确认框优先。`HelpActions` 从已注册的帮助键派生关闭帮助的操作；老板键和中断键也有公共定义。房间码等自由文本输入仍由输入组件处理；新增迁移时应保持这些上下文的优先顺序，并让展示与处理使用相同的操作定义。

同一时刻生效的动作集合可以用 `ValidateActions` 检查重复 ID、主键和别名冲突。检查应按实际场景分别进行：例如爆炸猫埋雷时 `I` 属于位置选择，不与普通场景的界面切换同时生效。不同模态可以复用按键；调用方负责先分派当前模态，再处理普通场景。该函数需要调用方显式调用，当前项目的操作表由测试检查，并非所有未来游戏都会自动验证。
