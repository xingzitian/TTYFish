# 账号注册与登录

账号使用固定、唯一的用户名。新用户先打开网页注册，用户名为 3–20 位小写字母、数字、下划线或短横线，以字母开头；注册后不能通过修改 SSH 命令中的用户名来更名。

注册时可填写 SSH 公钥、密码，或两者都填，至少提供一项。密码为 10–72 字节，数据库只保存 bcrypt 哈希。公钥填写 `.ssh/id_ed25519.pub` 的完整内容；私钥保留在玩家电脑上。账号页可以添加公钥、设置或修改密码。

## 进入游戏

密钥登录：

```sh
ssh -p 2222 -i ~/.ssh/id_ed25519 alice@服务器地址
```

密码登录（关闭本次连接的公钥尝试，直接提示输入密码）：

```sh
ssh -p 2222 -o PubkeyAuthentication=no -o PreferredAuthentications=password alice@服务器地址
```

`alice` 必须替换成注册时的固定用户名。未知用户名、其他账号的密钥或错误密码均不能进入游戏。未设置密码的账号只能使用密钥登录。同一账号的所有密钥与密码共享游戏身份和断线重连座位。

## 网页登录

已有账号可以直接输入用户名与密码登录网页，也可以填写用户名，获取 SSH 一次性确认命令，用绑定的密钥在终端执行。验证码只对对应账号有效。网页登录不会自动创建账号。

## 部署与旧数据

本机启动：

```sh
cd hub
go run ./cmd/hub -addr :2222 -http :8080
```

访问 `http://127.0.0.1:8080`。正式部署通过 `-ssh-hint "-p 2222 play@game.example.com"` 指定公网连接参数，页面会把 `play` 替换为玩家的固定用户名。对外网页应通过 HTTPS 提供，避免明文传输密码。

数据库启动时自动添加密码表，保留已有账号、用户名和公钥。已有账号必须使用账号页显示的原用户名，可以先通过原公钥登录网页再设置密码。SSH 连接不再自动创建账号。无账号库的纯游戏模式仍保留原来的密钥身份行为。

密码认证和注册按来源 IP 共用每分钟 10 次的限制；反向代理部署时当前按直连代理 IP 计算。

## 验证

运行 `cd hub`、`go test ./... -count=1`，覆盖注册冲突、凭证缺失、密码修改、跨站请求、跨账号公钥绑定及真实 SSH 握手。手动注册账号后，分别使用上面的两条命令验证游戏登录，再用错误用户名连接，确认被拒绝。
