## 第 1 步：解除 SSH 层与 UNO 的耦合（已完成）

原先 `hub/internal/sshd` 直接引用 UNO 的规则、渲染器和界面构造器。
替换游戏需要改动 SSH 接入代码，与架构中“平台不认识具体游戏”的目标不符。

本次改动：

- 新增 `hub/internal/registry`，用 `Entry` 绑定游戏标识、规则实例和 UI 工厂。
- 定义 `UIContext`，提供玩家身份、SDK 客户端、输出流、TERM 和颜色偏好回调。
- UI 工厂返回实现 `tea.Model` 和 `Close()` 的模型，SSH 连接结束时调用清理方法。
- `cmd/hub` 负责创建 UNO 规则、界面和渲染器，SSH 层只消费通用挂载项。
- 服务启动前检查游戏标识、规则实例和 UI 工厂是否齐全。
- 入口继续指定原有 `uno-prefs.json`，保留已有颜色偏好；SSH 服务标识改为 `TTYFish`。

当前边界：

- `hub/internal` 的非测试代码不再引用 `games/uno`；房间测试仍使用 UNO 验证行为。
- 目前只有单个挂载项，登录后仍直接进入 UNO；尚无多游戏查找和选择大厅。
- 游戏座位仍按公钥指纹识别，昵称来自 SSH 用户名；统一账号身份将在后续处理。
- 游戏专属规则开关仍在组装入口设置，规则实例与 UI 使用同一份配置。

## 本机测试（Windows PowerShell）

需要 Go 和 OpenSSH 客户端。模块要求 Go 1.26.0；启用自动工具链选择时，
Go 会在首次运行时下载所需工具链和依赖，需要网络及缓存目录写入权限。
以下命令从仓库根目录开始执行。

### 启动服务

```powershell
cd hub
go run ./cmd/hub -addr 127.0.0.1:2222 -http 127.0.0.1:8080 -host-key host_ed25519
```

保留窗口，另开一个 PowerShell 连接：

```powershell
ssh -t -p 2222 player@127.0.0.1
```

首次连接确认主机指纹。如果提示 `Permission denied (publickey)`，创建独立测试密钥：

```powershell
ssh-keygen -t ed25519 -f "$env:USERPROFILE\.ssh\ttyfish_test"
ssh -t -i "$env:USERPROFILE\.ssh\ttyfish_test" -p 2222 player@127.0.0.1
```

不要覆盖已有密钥。下面涉及 SSH 的手动测试，如果用了测试密钥，都加上同一个 `-i` 参数。

### 手动验收

| 项目 | 操作与预期 |
|---|---|
| 建房与对局 | 按界面提示建房、添加机器人并开局，检查出牌和摸牌 |
| 颜色偏好 | 修改颜色样式后退出重连，确认选择保留 |
| 断线重连 | 对局中关闭客户端窗口，60 秒内用同一密钥重连，应回到原座位 |
| 非交互连接 | 对局中另开窗口执行 `ssh -p 2222 player@127.0.0.1 true`，原游戏连接不应被顶掉 |
| 多人加入 | 用另一把密钥连接，输入同一房间码，两名玩家应拥有独立座位 |
| 网页登录 | 打开 `http://127.0.0.1:8080`，执行页面展示的 SSH 挑战命令，确认能进入账号页 |

同一密钥换用户名仍是同一个玩家。测试多人时必须使用不同密钥。
测试完成后在服务端窗口按 `Ctrl+C` 停止服务。

## 第 2 步：多游戏注册表与平台大厅（下一步）

实现内容：

1. 在 `internal/registry` 增加按游戏标识注册、查找和列举的能力，拒绝重复标识。
2. 增加平台大厅界面，SSH 登录后展示游戏列表，选择后进入对应游戏 UI。
3. 房间绑定游戏标识，明确房间码的查找范围，避免进入错误游戏的房间。
4. 重连优先恢复原房间及其游戏，避免玩家必须重新选择游戏。
5. 明确从游戏返回大厅时的订阅释放和座位处理，避免残留连接或重复订阅。

验收标准：

- UNO 的建房、对局、偏好和断线重连继续正常。
- 用第二个最小测试游戏验证列表、UI 切换和房间隔离。
- 接入另一个游戏时只需新增游戏模块依赖和入口注册，不改 SSH 或房间的通用实现。

## 第 3 步：统一账号身份

- 交互式 SSH 登录时查找或创建账号。
- 房间使用账号 ID 识别玩家，昵称从账号资料获取。
- 同一账号下的不同公钥能够恢复同一座位，并遵循一致的顶号策略。
- 处理现有指纹索引的颜色偏好迁移，确保账号绑定不会丢失偏好。

验收标准：为同一账号绑定两把密钥，用其中任意一把连接都识别为同一玩家；
未绑定到同一账号的密钥仍是不同玩家；网页登录与游戏身份一致。
