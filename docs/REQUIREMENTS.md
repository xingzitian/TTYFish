# TTYFish 平台需求

> 一句话：**用 SSH 当客户端、用公钥当账号的多人小游戏平台。**
> 平台负责"人和房间"，游戏只负责"规则和画面"，两者是两个独立项目。

状态标记：`P0` 必须有（第一版就要）· `P1` 应该有（很快补）· `P2` 以后再说

---

## 1. 角色

| 角色 | 想要什么 | 关键约束 |
|---|---|---|
| **玩家** | `ssh hub` 就进大厅，不用注册、不用记密码 | 零客户端安装，终端里能用 |
| **游戏作者** | 写一个游戏，提交上来就能被人玩到 | 只实现 SDK 接口，不碰账号/房间/网络 |
| **运营者** | 一个二进制 + 一个 SQLite 文件就能跑 | 单机部署，不依赖外部服务 |

---

## 2. 账号与身份

### 2.1 核心模型

账号 **不是** 公钥。一个账号可以挂多把公钥，公钥可以增删。

```
accounts   账号本体（id / handle / 昵称 / 头像文字 / 创建时间）
identities 凭证（账号 id / 类型 ssh / 公钥 / 指纹 / 加入时间 / 最后使用）
```

理由：用户换机器、换密钥、加第二把备用钥匙时，社交关系和战绩不能丢。

### 2.2 需求

- `P0` 首次连接即注册：SSH 握手时出示公钥并签名，验证通过就建号（TOFU）
- `P0` 同一个指纹再连 = 同一个人，自动登录
- `P0` handle 唯一、可改；SSH 用户名只作为默认昵称建议，不参与身份
- `P1` 一个账号挂多把公钥（网页上加/删）
- `P1` 每把公钥记录"最后使用时间 / 来源 IP"，异常时可排查
- `P1` 删除最后一把公钥前必须提示"删了你就进不来了"，且要求先挂新的
- `P2` 账号合并（两个人各自建号后想并成一个）
- `P2` 封禁（按账号 / 按公钥指纹）

### 2.3 故意不做

- **不做密码**：没有密码就没有"忘记密码"，也不需要邮件服务
- **不做邮箱**：恢复手段是"挂第二把公钥"，和 GitHub 一个思路
- **不把指纹当主键**：指纹是派生值，换钥匙就变了

## 3. 登录

### 3.1 终端（P0）

- `P0` `ssh hub` 交互式进入 → 大厅
- `P0` 无需任何注册步骤，第一次连就是注册
- `P0` 断线 60 秒内重连座位还在

### 3.2 网页（P0，第一版只做这一种方式）

**SSH 挑战登录**：浏览器给一次性码，用户在终端执行 `ssh hub auth <码>`，浏览器自动登入。

```
浏览器                     hub                         终端
  │ POST /auth/ssh/start     │                            │
  │────────────────────────► │ 生成码（32B 随机）           │
  │ ◄── 显示码 + 轮询地址     │                            │
  │                          │ ◄── ssh hub auth 8F3A9C ───│
  │                          │  验签 → 找/建账号 → 标记    │
  │ GET /auth/ssh/poll       │                            │
  │ ◄── Set-Cookie: session  │                            │
```

- `P0` 码：单次使用、90 秒过期、与发起登录的浏览器会话绑定
- `P0` 成功后 `Set-Cookie`（HttpOnly + SameSite=Lax）
- `P1` 按 IP 限流（失败 5 次 / 分钟）
- `P1` Passkey（WebAuthn）作为第二种登录方式，同一个账号可以两种都挂
- `P2` 设备管理：列出所有网页会话，可单独踢掉

### 3.3 安全约束（P0）

- 挑战码只存哈希，不存明文
- 挑战码不能被用来枚举（随机 32 字节，不存在递增）
- SSH 端 `auth` 命令只接受 `auth <码>` 这一种形式，其它 exec 命令一律拒绝
- 登录成功/失败都写日志（账号、指纹、IP、时间）

## 4. 大厅与房间

### 4.1 终端入口（P0）

```
ssh hub                → 大厅：我的账号 / 游戏列表 / 在线好友
ssh hub join ABC234    → 直接进某个房间（分享链接用）
ssh hub auth <码>      → 网页登录
```

- `P0` 大厅里能看到"有哪些游戏可玩"，选一个进去
- `P1` 谁在线、在玩什么
- `P2` 一键邀请好友（生成带房间码的链接）

### 4.2 房间（P0，已有实现，迁进平台）

- `P0` 6 位房间码（去掉 0/O/1/I）
- `P0` 2~6 人（具体上限由游戏声明）
- `P0` 房主开局、补电脑、掉线 60 秒托管、重连回座
- `P0` 顶号：同一账号的新连接接管旧连接
- `P0` 投票重开
- `P0` 预设快捷语（不做自由输入，避免控制字符注入）

### 4.3 房间元数据（P1）

- 房间列表：谁开的、什么游戏、几个人、能不能进
- 房间回收：空房立即回收，断线满 10 分钟回收

## 5. 游戏接入

### 5.1 游戏是什么

一个游戏 = 一个 Go 模块，实现 SDK 的 `Game` 接口 + 提供一个终端 UI。

- `P0` 注册后出现在大厅列表里
- `P0` 游戏不接触账号、房间、网络、终端
- `P0` 信息裁剪只有一个入口（`Observe`），AI 和观战共用
- `P1` 游戏声明自己的规则选项，玩家在开局前选
- `P2` 第三方提交的游戏走"仓库地址 + 版本"登记

### 5.2 不做什么

- 不提供图形、不做实时语音
- 不允许游戏直接读写数据库（要存东西走平台的键值接口）

## 6. 战绩与社交

### 6.1 战绩（P1）

- 每局结束记一条：游戏、时间、参与者、名次、分数
- 个人页：最近 N 场、胜率、总时长
- 排行榜（P2）

### 6.2 社交（P2）

- 好友（申请/通过）
- 在线状态（在哪个游戏、是否可加入）
- 观战（晚点再说）

## 7. 非功能需求

| 项 | 要求 |
|---|---|
| 部署 | 一个二进制 + 一个 SQLite 文件；不需要 Redis/消息队列 |
| 依赖 | 纯 Go 静态编译（不打 cgo），`CGO_ENABLED=0` 能过 |
| 平台挂了 | 已登录的游戏会话不受影响；新连接降级为"游客可玩" |
| 账号服务挂了 | 游戏服使用缓存的指纹→账号映射，继续能打牌 |
| 数据 | SQLite WAL 模式；每天自动备份一次（保留 7 天） |
| 可观测 | 每分钟一行：连接数 / 房间数 / goroutine 数 / 内存 |
| 容量目标 | 单机 200 并发连接、50 个房间无压力 |

## 8. 里程碑

| 版本 | 内容 | 验收 |
|---|---|---|
| **M0** | 平台骨架：HTTP + SQLite + SSH 挑战登录 | 浏览器点登录 → 终端敲命令 → 网页已登录 |
| **M1** | 账号：自动建号、多公钥、网页"我的钥匙" | 换机器换把钥匙还是同一个人 |
| **M2** | 游戏挂载：大厅选游戏，uno 迁入 | `ssh hub` 进大厅，选 uno 开打 |
| **M3** | 战绩 | 网页能看到最近 20 场 |
| **M4** | 社交（好友、在线、邀请） | 能拉人 |

## 9. 术语

| 词 | 含义 |
|---|---|
| **指纹** | 公钥的 SHA256 摘要，用来认人 |
| **TOFU** | trust on first use，第一次见到的公钥就认作新账号 |
| **挑战码** | 网页生成、终端消费的一次性登录码 |
| **座位** | 房间里的一个位置，和连接解耦；掉线座位保留 60 秒 |
| **裁剪** | `Observe`：决定某个座位能看到什么，是全项目唯一的信息出口 |
