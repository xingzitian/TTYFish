# 认证与会话升级设计

本文记录认证会话的行为与部署约束；当前工作区尚未发布。

## 会话模型

- Web 登录以账号和浏览器设备标识为单位，设备标识仅用于分组，不用于认证。登录成功后原子替换该设备先前的登录。
- 浏览器持有 HttpOnly 刷新 Cookie，访问令牌仅在内存中。刷新和登出接口必须校验可信 Origin，生产 Cookie 必须使用 Secure。
- 终端会话按账号接管。仅交互式 PTY 会话可以取得租约；公钥探测、SSH 挑战确认和其他 exec 请求不得接管终端。
- 关闭终端时释放租约，异常断线由租约超时回收。旧连接释放时必须校验租约 ID，避免误删新连接。

## 需要覆盖的边界

- 多个浏览器标签页可能同时刷新，同一次轮换不能把正常并发误判为盗用；跨标签页协调、响应丢失及重试都需要明确处理。
- 设备标识来自客户端，可以被重置或复制，不能证明物理设备身份。
- Web 的登出、撤销其他会话、删除关联 SSH 公钥、修改密码时的撤销策略必须同时撤销相应刷新能力和访问令牌。
- SSH 登录与 SSH 挑战确认共享握手流程，只有确认交互式会话后才能执行终端接管。
- 会话列表应区分有效 Web 登录与在线终端；关闭浏览器不等于可靠登出，不能将长期登录误称为在线。
- 现有部署以 HTTP 地址为例；生产启用 Secure Cookie 前需要 HTTPS 和同源代理，开发环境须显式配置本地例外。
- 旧版会话的迁移和失效策略、OpenAPI 契约、部署配置、回滚及跨版本兼容均需随实现同步。

## 当前接口和部署

- 浏览器密码登录和 SSH 挑战领取带 `X-Device-ID` 时，返回 15 分钟 Bearer 令牌并设置刷新 Cookie。`POST /api/v1/auth/refresh` 在 Cookie 有效时轮换它；令牌重放撤销该组会话。刷新时返回的 Cookie 有效期不会延长服务端 30 天的绝对期限。
- 默认 Cookie 名为 `__Host-ttyfish_refresh`，属性为 `Secure; HttpOnly; SameSite=Strict; Path=/`。生产必须使用 HTTPS，同源反向代理转发 `/api` 和 `Set-Cookie`，并将前端来源加入 `-cors-origins`。`-insecure-web-cookies` 仅用于本机 HTTP；它使用不同 Cookie 名称。
- 网页启动时静默刷新；支持 Web Locks 的浏览器会跨标签页串行化登录、刷新和退出。刷新响应丢失或不支持 Web Locks 的浏览器并发刷新，可能触发重放保护而需要重新登录。刷新令牌无法防止 XSS 通过当前页面发出已认证请求。
- `GET /api/v1/me/sessions` 包含未撤销且未过期的 Web 设备会话和旧版未过期会话；`GET /api/v1/me/terminal` 单独返回在线 SSH 终端。列表中的 Web 会话代表仍有登录权限，不代表浏览器在线。
- 终端租约每 10 秒续期，有效期 60 秒；接管通知通过 SSE 发送，心跳处理事件流中断。正常退出释放租约，异常断线超时后不再显示。SSH 连接的公钥指纹不是物理设备标识。
- `GET /api/v1/me/login-history?channel=web|ssh&offset=0&limit=10` 仅返回本人成功登录的归并历史。Web 按浏览器配置归并，SSH 按认证方式、公钥指纹和来源 IP 归并；先对全部保留记录归并再按组分页，组内包含每次事件。最多返回 50 组，保留 30 天且每账号最多 1000 条。仅记录升级后事件，不回填旧数据；历史中的密钥名称为登录时快照。
- Web 密码登录、SSH 挑战领取产生的设备会话以及交互式 SSH 租约取得时写入成功事件，刷新令牌、失败认证、非交互 SSH 确认不新增事件。历史写入与设备会话或终端租约在同一事务，写入失败会阻止该次会话建立。SSH 状态 `closed` 为观察到连接关闭，`replaced` 为被新终端接管，`lost` 为租约超时或凭证失效且结束方式未知，其时间是最后一次心跳而非精确断线时刻。
- 旧版 Bearer 会话保持原有效期，但没有刷新能力；升级后重新登录才能获得持久 Web 会话。回滚到旧版后不能使用新刷新 Cookie，需重新登录；备份 SQLite 后再升级或回滚。
- Web 访问令牌只保存哈希；令牌被清理后，其哈希到会话的归属会保留至会话过期，以便安全退出。退出时若访问令牌与刷新 Cookie 属于不同会话，或访问令牌归属未知，服务端拒绝该请求，不撤销也不清除另一会话的 Cookie。升级时会补录仍存在的访问令牌归属；更早已清理的令牌无法回填，可先刷新再退出。
- 刷新时账号读取与令牌轮换处于同一事务；数据库故障会回滚轮换并保留浏览器 Cookie。只有确认凭证无效、过期、已撤销或重放时才清除 Cookie。事务提交后若响应在网络中丢失，仍可能需要重新登录。
